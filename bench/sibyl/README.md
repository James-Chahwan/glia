# The Sibyl matrix, synthetic side

Generated repos with known answers, one per case of a pairwise cover of the ways a client
reaches a server (FH.11, James 2026-10-26: "our synthetic sybil matrix of resolvers and code
languages and mix and match combos"). Every combination of the axes below is thousands of
repos; a pairwise cover (each pair of axis values together in at least one case) is a few
dozen and catches the two-factor interactions that broke immich (an enum route prefix behind
a workspace SDK). The real-repo side is the cohort (`bench/cohort/`, FH.1) and its grades in
the coverage matrix (FH.10): the cohort says which combos occur, this matrix says which work.

- `gen.py` - the axes, the unexpressible pairs, the cover, rendering (below).
- `templates/` - one module per transport (`rest.py` places and assembles a case,
  `rest_clients.py` / `rest_servers.py` hold one template function per client / server value,
  `common.py` the exchange, the renamed field and `norm_path`). FH.11b adds gRPC, GraphQL,
  queue and WebSocket modules and `run.py`, which builds each case with the glia under test.
- `test_gen.py` - hermetic tests: `python3 bench/sibyl/test_gen.py`.

## Axes

| axis | values |
|---|---|
| `client` | `ts`, `dart`, `kotlin`, `swift`, `python` |
| `server` | `go-gin`, `ts-nest`, `ts-express`, `java-spring`, `python-fastapi`, `rust-axum`, `csharp-aspnet` |
| `transport` | `rest`, `grpc`, `graphql`, `queue`, `websocket` |
| `wiring_source` | `literal`, `const`, `enum-prefix` |
| `wiring_call` | `direct`, `wrapper`, `generated-sdk` |
| `packaging` | `single`, `workspace`, `multi-repo` |
| `contract` | `declared-type`, `schema-object`, `plain-literal`, `generated` |

- `wiring_source` is how BOTH sides spell the path: inline (`literal`), a constant prefix
  (`const`: `API_PREFIX = "/api/v1"`), or the resource segment from an enum (`enum-prefix`:
  immich's `@Controller(RouteKey.Users)` under a global prefix; Go's typed `RouteKey` const,
  Python's `StrEnum`, Dart / Kotlin / Swift enums on the client).
- `wiring_call` is how the client calls: at the use site (`direct`: fetch, package:http, OkHttp,
  URLSession, httpx), through a hand-written `apiGet(path)` helper (`wrapper`), or through an
  SDK as openapi-generator writes it for that language (`generated-sdk`: a literal operation
  path under a base-path constant, a "Generated by OpenAPI Generator" header).
- `packaging`: client and server in one repo (`single`); one repo whose app imports its api
  layer from a workspace package (`workspace`: pnpm, pub, Gradle, SwiftPM local package, uv);
  two repos, built with `--with` (`multi-repo`).
- `contract` is the client's model of the payload: an interface / class / struct
  (`declared-type`), a runtime schema (`schema-object`: Zod, json_serializable,
  kotlinx.serialization, Codable CodingKeys, Pydantic), an untyped object (`plain-literal`), or
  a generated model file (`generated`). The server writes its own idiomatic model (Go struct,
  Nest DTO class, TS interface, Java record, Pydantic model, serde struct, C# record).

The server values are one framework each: Go is gin, Python is FastAPI, Rust is axum, Java is
Spring Boot, C# is ASP.NET Core controllers.

## Unexpressible pairs

The cover never asks for these; each is a pair no stack of the matrix writes idiomatically.

| pair | why |
|---|---|
| `generated-sdk` x `enum-prefix` | SDK generators write a literal operation path under a base-path constant, never an enum |
| `generated-sdk` x `declared-type` | an SDK generator writes its own models: a generated SDK's contract is generated |
| `generated-sdk` x `schema-object` | (same) |
| `generated-sdk` x `plain-literal` | (same) |
| `java-spring` x `enum-prefix` | Spring mapping annotations take compile-time constant strings; an enum constant is none |
| `csharp-aspnet` x `enum-prefix` | ASP.NET route attributes take constant strings; an enum member's name is none |
| `rust-axum` x `enum-prefix` | axum routes take `&str`; Rust code names a route prefix with a const, not an enum |
| `grpc` x `direct` | a gRPC call goes through a stub; there is no hand-written request at the use site |
| `grpc` x `enum-prefix` | a gRPC method path is `/package.Service/Method` from the .proto; there is no URL prefix |
| `graphql` x `enum-prefix` | GraphQL posts every operation to one endpoint; there is no resource segment to prefix |
| `grpc` x `plain-literal` | protobuf messages are declared in the .proto and generated |
| `grpc` x `schema-object` | (same) |
| `grpc` x `ts-express` | Express serves HTTP/1 routes; a Node gRPC server is grpc-js, another stack |
| `grpc` x `python-fastapi` | FastAPI serves HTTP routes; a Python gRPC server is grpcio, another stack |
| `queue` x `dart` | a Flutter app does not hold a broker connection; it reaches queues through a server |
| `queue` x `swift` | an iOS app does not hold a broker connection; it reaches queues through a server |

A transport module may add rows (`UNEXPRESSIBLE` in its module, merged by `gen.unexpressible()`).
A pair that is allowed alone but that no full case can hold would be printed as
`implied_unexpressible=<n>` on the marker line; the current table implies none.

## The cover

`python3 bench/sibyl/gen.py cover [--transports rest] [--seed 54] [--json]` prints the cases
and, on stderr, `[sibyl] cover cases=<n> pairs=<p>/<t> transports=rest` (`p` the expressible
pairs the cases hold, `t` all of them; the two are always equal). The algorithm is greedy IPOG
(In-Parameter-Order): axes largest first, horizontal growth by the value covering the most
uncovered pairs, vertical growth for the rest, every step kept extendable to a full case with
no unexpressible pair; ties go to a `random.Random(54)`, so the cover is a function of the
axes, the table and the seed. A case id is `<transport>-<nnn>-<client>-<server>`. Over REST it
is 37 cases holding 272 pairs (the floor is client x server = 35); over all five transports, 41.

## A case

Each case has one exchange, `GET /api/v1/users/{id}` returning `{id, displayName, email}`, and
one rename drift in three states:

- `P` - base: both sides use `displayName`.
- `S` - the server renamed it to `fullName`; the client is stale (the drift).
- `C` - the client follows (clear).

`python3 bench/sibyl/gen.py render --out DIR [--case ID].. [--trees]` writes, per case,
`DIR/<id>/expected.json` and each repo as git (`DIR/<id>/repo/`, or `client/` and `server/` for
`multi-repo`) with commits P, S, C (at `refs/sibyl/<state>`, fixed identity and dates, so every
render is byte-identical; an unchanged repo gets an empty commit, so `HEAD~1` is always the
previous state); `--trees` writes plain `DIR/<id>/<state>/<repo>/` trees instead. Render into a
cache directory, never the repo.

`expected.json` is read off the renders, never written by hand:

- `pair` - `HTTP_CALLS` from the client file naming the route (`pair.client.file`: the call
  site, or the generated SDK file) to the server route (`route_file`, `handler`,
  `handler_file`, `model_file`); `exchange.path_norm` is the path with every parameter segment
  `{}` (`gen.norm_path` maps `{id}`, `:id`, `<int:id>`, `${…}`, `$id`, `\(id)` to it).
- `reader` - the app file reading the field across the api layer.
- `drift` - the field (`old` / `new`, a response field), `server_files` (what P..S changed) and
  `client_files` (what S..C changed: the truth a drift answer must name), flagged at `S`,
  clear at `C`.
- `primary` / `with` - the repo whose change starts the drift is built, the others join with
  `--with`.

## The tests

`python3 bench/sibyl/test_gen.py` checks, with no glia and no network: the REST and the
all-transport covers hold every pair a brute-force enumeration of the full product says is
expressible, and none of the table; the cover is deterministic and moves with the seed; every
axis value renders; the expected files exist in every state and the drift holds by
construction (S's server files spell only the new name, every S..C client file the old one at
S and the new one at C); the layouts; the git form (three commits per repo, the refs, the same
heads on two renders). Then every rendered file is parsed by a parse-only toolchain where one is
present: TypeScript `transpileModule` diagnostics (a `typescript` package from `SIBYL_TYPESCRIPT`,
`npm root -g` or the npx cache), `gofmt -e`, `rustfmt --emit stdout`, javac's parse phase,
`dart format`, `swiftc -parse`, Python `ast`, and JSON / TOML / XML / YAML readers. Each checker
first has to reject a broken file (the control). Kotlin and C# have no parse-only toolchain, and
an absent one is skipped; skips are counted on
`[sibyl] syntax checked=<n> skipped=<m> (<lang>:<files> <reason>, ..)`. Temporary trees go
under `$SIBYL_TMP` (default `~/.cache/glia-sibyl-test/`).

Templates stay tiny and idiomatic, or the matrix tests the generator: each mirrors the shape of
that stack's real code (the generated SDKs follow openapi-generator's output for the language,
the enum prefix immich's `RouteKey`).
