# repo-graph handoff — review-2026-09-15 §1–§3 programme (glia side)

Everything in this programme is **API-additive**: no pyo3 or CLI method was renamed or removed, new parameters default
to off, and no NodeKind/EdgeCategory/CellType id was renumbered. What changed is **graph content** — the rule agreed
up front was that wrong edges may be removed and qname shapes fixed, with each change listed here for the repo-graph
session. This file is that list, generated from what each packet DECLARED in its result, not from memory.

- Packets landed: 105 of 105 across 19 waves. Missing results: none.
- Deliberate contract breaks: **none shipped.** The one parked item is A6.6's persisted `interface_methods` (a .gmap
  layout change) — for the joint repo-graph + glia version.

## Before you bump the wheel pin in repo-graph

1. **New registry ids exist** (allocated centrally in wave 0, `code-domain/src/lib.rs`): node_kind 45 PROJECT, 46 MESSAGE_TYPE,
   47 GRPC_SERVER, 48 RPC_PROCEDURE, 49 RPC_CALL; edge_category 33 SHARES_DATA_SOURCE, 34 RPC_CALLS; cell_type 17
   MESSAGE_TYPE, 18 RPC_PACKAGE. **Confirm the wrapper decodes via `kind_names()` / `category_names()` / `cell_type_names()`**
   and not a frozen local table — the old "decode tables frozen 40/31" note means new ids could render as UNKNOWN.
2. **The parse cache and .gmap manifest are now keyed on a build stamp** (A1.1/A1.2), not just the release version: the first
   build after upgrading reparses everything once. Expected, not a regression.
3. `repo_graph_py.build_stamp()` now reports which code a wheel contains — use it to rule out a stale install.

## For in-process Rust consumers (neuropil, engram-export) — not repo-graph

`repo_graph_engine::GenerateResult` gained a fifth public field, `repo_labels: BTreeMap<u64, String>` (A9.2). It is not
`#[non_exhaustive]`, so **any code that builds it with a struct literal will not compile**. Reading it is unaffected. In this
repo only the engine constructs it, and `engram-export` and `bench/tui-viewer` both compile cleanly against the new engine.
**neuropil was not checked** — it is a separate repo; verify there before bumping its glia path/pin.

`glia --version` output changed from `glia 0.4.13` to `glia 0.4.18 (build 0.4.18+p<hex>)` — anything parsing it should
match on the leading `glia <semver>`.

- pyo3 `PyGraph`: `service_map()`, `contracts()`, `project_roots()`, `parse_errors`, `build_stamp()` (module fn); `generate_many(..., incremental=False)`;
